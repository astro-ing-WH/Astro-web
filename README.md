# 项目管理平台（边缘智算 · 决策直达）

一个面向工程施工现场的**个人项目管理平台**原型，用于演示“数据只录一遍、信息直达决策”的完整链路。项目为纯静态单文件网页，无后端、无外部依赖，可直接在浏览器打开或部署到 GitHub Pages。

---

## 1. 项目解决什么问题

施工现场真正低效的地方，不是“没有系统”，而是**同一份数据被反复填报、层层转发、反复加工**。

- **同一数据反复录**：一根柱子浇筑完成后，施工员、采购、质量、财务、合同、资料员要各自再填一遍表，口径还不一致。
- **信息多级换乘**：现场 → 项目部 → 公司条线 → 管理层，往往要经过 4~5 层、6 次传递，才能到达真正做决策的人。
- **管理端看到的是资料堆**：汇总上来的是成百上千份表格和附件，而不是“进度到哪、质量如何、风险在哪”的状态。
- **预警到不了该到的人**：要么全部堆到公司，项目部失去纠偏权；要么长期停留在现场，没人督办。
- **一线不会用**：系统字段多、流程长，老员工学不会，最后仍然回到微信和纸质表。
- **边缘应用各自为政**：现场做了很多小程序，但没有人统一管理、统一校验、统一检索。

本平台把上述问题拆成一条可演示的链路：**现场只拍照/录表 → 边缘端识别与校验 → 只回传结构化结果 → 管理端只看状态、只做督办**。

## 2. 主要功能

平台采用“左侧导航 + 右侧工作区”结构，共 13 个模块，分为 5 组。

### 2.1 管理视角

**01 驾驶舱**
- 4 个核心指标：在建项目、本月完成产值、待处置预警、具备创优条件项目。
- “六笔账”：同一个构件 `1F-KZ01 · C40`，分别呈现进度、质量、材料、计量、付款、审计六个角色看到的不同结果。
- 项目总览表：按形象进度排序，展示阶段、进度、质量状态、预警、创优。
- 材料消耗与进度交叉验证说明。

**02 分级预警**
- 三次升级规则：
  - 第 1 次：提醒项目管理人员，给出处置建议与时限；
  - 第 2 次：项目内升级，抄送公司条线负责人，仍由项目部处置；
  - 第 3 次：同周期三次未回复，升级公司督办。
- 当前预警列表示例，覆盖一级黄色、二级橙色。
- 两类典型预警：边坡滑塌风险、质量与进度偏离。

### 2.2 现场作业

**03 技术交底**
- 方案录一遍，审核、交底、执行一条链贯通。
- 五步流程：方案编制 → 审核批准 → 技术交底 → 班组签收 → 现场执行。
- 记录交底对象、交底内容、附件（施工图、三维交底）与签收状态。

**04 施工日志生成**
- 一页录入：天气、基本信息、施工内容、质量安全、人员、派工与机械、现场照片。
- 内置 A4 打印填报工具，本机保存、可离线使用。

**05 混凝土小票录入**
- 演示拍照/识别 → 自动填表。
- 8 个结构化字段：构件编号、强度等级、设计方量、实际浇筑量、坍落度、试块组数、GPS 定位、拍摄时间。
- 6 项规则校验：GPS 红线、拍摄时间与工序匹配、坍落度 160±20mm、试块组数、方量与材料批次、小票/照片/工序/日志关联。
- “核验通过 · 同步”后，同一数据同步更新六条线：
  - 进度 · 总工
  - 材料 · 采购
  - 计量 · 商务
  - 付款 · 财务
  - 审计 · 法务
  - 公司 · 驾驶舱
- 明确边界：材料消耗只作交叉信号，不替代合同计量。

**06 工序验收**
- 按标准工序链推进，每道工序明确“拍什么、传什么、验什么”。
- 工序完成即上传举牌验收照片与检测数据，当天归档。

### 2.3 业务条线

**07 地质调查与报告**
- 现场录入点位编号、坐标、岩性、产状、风化程度、地下水与现场描述。
- 一键生成野外地质原始记录表，避免回室内二次誊写。
- 只同步结构化结果，原始照片留存在本地。

**08 合同与创优**
- 合同上传一遍，自动拆成 A / B / C / D 四类字段：
  - A 施工大类
  - B 金额分类
  - C 创优要求
  - D 工期与付款
- 命中创优条款后自动进入创优项目清单，支持按字段检索。

**09 质量条线**
- 四条子线：材料送检、样板引路、材料消耗、工序验收。
- 数据由项目部上传，管理端只调取、只读，不代替项目部管理。
- 样板考核与奖罚由项目部决定和执行。

### 2.4 数据底座

**10 数据框架**
- 六级穿透：公司 → 项目 → 子工程/阶段 → 作业对象 → 工序节点 → 资料记录。
- 8 个核心实体：项目、子工程、作业对象、工序节点、资料记录、材料批次、试块、施工日志。
- A~G 资料分类：
  - A 工序验收资料
  - B 材料质保资料
  - C 过程检测数据
  - D 施工计量数据
  - E 过程影像资料
  - F 试块管理资料
  - G 施工日志
- 交叉验证：GPS 与项目红线、拍摄时间与工序、方量与材料批次/试块、日志/验收/计量互相印证。

**11 房建工序体系**
- 九阶段工序链与作业对象定义，展示各阶段工序节点、核心实体与资料对应关系。

### 2.5 方案归档与 AI 管家

**12 方案与路演**
- 内置 6 份材料，均以弹层方式在线查看：
  - AI 赋能业务创新方案书
  - 参赛方案：边缘智算 · 直达决策
  - 路演文稿
  - 宣讲展示
  - 三步逻辑总汇总
  - 数据只录入一遍 · 审阅稿

**13 AI 管家**
- “用 AI 管理 AI”：统一管理各边缘应用。
- 三件事：校验上传结果、统一检索、分级预警。
- 提供对话示例，可按项目上下文检索、追问。

### 2.6 全站通用能力

- 双主题首屏：左侧深色科技风个人主页，右侧浅色专业风系统入口。
- 个人作品主页：AI 架构师身份、能力方向、作品时间线、方法理念。
- 全局检索：输入关键词后联想匹配，并自动跳转到对应模块。
- 文档弹层：嵌入式文档统一在模态框中打开，不离开平台。
- 离线可用：所有页面、样式、脚本、文档均内嵌，无网络也可打开。

## 3. 核心设计

### 3.1 核心链路

```text
现场拍照 / 录表
      ↓
边缘端识别、结构化、规则校验
      ↓
只回传结构化结果（不上传原始照片）
      ↓
管理端驾驶舱 / 分级预警 / 统一检索
```

### 3.2 四个核心原则

1. **数据只录一遍**
   同一数据对象只录入一次，后续六条业务线自动复用，不再各自填表。

2. **边缘计算，结果直达**
   OCR、分类、校验放在离现场最近的地方完成；管理端只接收结果，不接收资料堆。

3. **车同轨、书同文**
   统一编号体系（六级穿透）与统一资料分类（A~G），知道编号就能一跳直达。

4. **纠偏权先留给一线**
   预警先到项目部，三次未回复才升级公司督办，避免“机器发现问题、公司直接接管”。

### 3.3 核心优势

- **不重建大平台**：管理端只做管家，不替代现有项管平台，也不处理原始数据。
- **低成本、可复制**：边缘应用按统一规范接入，换业务场景只需替换模块。
- **一线零门槛**：现场只做三件事——拍照、确认、提交。
- **数据可追溯**：合同、验收、计量、发票、资金流形成闭环证据链。
- **可演示**：从 `1F-KZ01` 一张小票出发，现场演示六条业务线同步更新。

## 4. 技术实现

- **纯静态单文件**：`index.html`，HTML + CSS + 原生 JavaScript。
- **无后端、无外部依赖**：不引用外部 JS/CSS/图片，断网可用。
- **文档内嵌**：方案书、路演稿等 6 份 HTML 以 Base64 内嵌，运行时通过 `Blob URL` 加载。
- **本地存储**：施工日志工具使用 `localStorage` / IndexedDB 本机保存。
- **拍照能力**：支持 `getUserMedia` 调用摄像头，也支持电脑端粘贴图片。
- **A4 打印**：施工日志提供 `@media print` 打印样式。
- **视图切换**：首屏、个人主页、系统工作区三种视图。
- **模块切换**：侧栏 `data-pane` 与工作区 `#pane-*` 一一对应。

> 说明：平台当前为演示原型，驾驶舱、预警、项目数据均为示例数据；混凝土小票 OCR 为交互演示，未接入真实识别服务。

## 6. 使用方式

### 本地打开

直接双击 `index.html`，用 Chrome / Edge 打开即可。

### GitHub Pages

1. 将 `index.html` 与 `README.md` 上传到仓库根目录。
2. 进入仓库 `Settings` → `Pages`。
3. 分支选择 `main`，目录选择 `/ (root)`，保存。
4. 访问 `https://<用户名>.github.io/<仓库名>/`。

## 7. 适用边界

- 本平台是**演示与方案验证原型**，不是可直接投产的正式系统。
- 不替代现有 OA / 项管平台，只接收边缘端回传的结构化结果。
- 材料消耗数据仅用于交叉验证，最终工程量仍按图纸、清单、变更和合同计量规则确认。
- 付款节点只形成条件清单并发起审核，不自动付款。
- 质量考核与奖罚由项目部决定和执行，管理端只查看状态。
